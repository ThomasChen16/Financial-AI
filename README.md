# Financial AI — RAG over Earnings Transcripts

Ask questions in plain English about uploaded PDF/DOCX transcripts (earnings calls, for
example) and get answers **grounded in the actual document text**, generated by a local
LLM via [Ollama](https://ollama.com). No API keys, no cloud — everything runs on your
machine.

It's a full [RAG](https://en.wikipedia.org/wiki/Retrieval-augmented_generation)
(Retrieval-Augmented Generation) pipeline: index your documents once, then ask anything.

---

## What it does

```
  INDEXING (once per file)                       QUERYING (per question)

  upload PDF/DOCX                               user question
       |  parser.py  extracts plain text              |  embeddings.py  converts to vector
       v                                               v
  plain text                                        query vector
       |  chunker.py  ~500-char chunks + overlap        |
       v                                                |
  chunks ──> embeddings.py ──> 384-dim vectors          |
                                 |                      |
                                 v                      v
                        FAISS index  <──similarity search (top-5)
                                 |
                                 v
                          relevant chunks
                                 |
                                 v
            llm.py ──> Ollama (llama3.2:3b) ──> answer
```

Indexing happens **once per uploaded document**. Querying happens **every time a
question is asked** — embed the question, find the 5 most similar chunks, hand them to
the LLM, return the answer.

---

## How it works, endpoint by endpoint

### `POST /upload` — index a document

1. Validates the extension (`.pdf` / `.docx` only; anything else → **400**) and saves
   the file to `data/uploads/` (gitignored).
2. `app/parser.py` extracts the text — `pdfplumber` page-by-page for PDFs,
   `python-docx` paragraph-by-paragraph for DOCX files.
3. `app/chunker.py` cuts the text into ~500-character chunks with a 50-character
   overlap, so an idea that spans a cut point isn't lost.
4. `app/embeddings.py` converts every chunk into a **384-dimensional vector** using the
   `all-MiniLM-L6-v2` sentence transformer, unit-normalized for cosine similarity.
5. `app/store.py` adds the vectors to a FAISS index (`IndexFlatIP`) alongside the
   original chunk texts, then persists both to `data/indexes/default.index` plus a
   `.texts.json` sidecar.
6. Returns `{filename, chunks, pages, index_total}`.

> **Persistence:** on startup, the API reloads the last-saved index — documents stay
> queryable across server restarts.

### `POST /ask` — get an answer

1. Validates the input: non-empty question, max 10,000 characters, and at least one
   document already indexed (otherwise → **400**).
2. Embeds the question with the same model and retrieves the **top-5 most similar
   chunks** from the FAISS index.
3. `app/llm.py` builds the prompt — a system message ("answer using ONLY the context,
   otherwise say so") plus the retrieved chunks and the question — and posts it to
   Ollama at `http://localhost:11434/api/chat` with the `llama3.2:3b` model.
4. Returns `{question, answer, results}` — `results` are the retrieved chunks with
   their similarity scores.

> **Graceful degradation:** if Ollama can't be reached, `/ask` still returns HTTP 200,
> but `"answer"` contains `"Unable to generate an answer: ..."` instead of crashing.

### `GET /health` — alive check

Returns `{"status": "ok", "index_total": N}` where `N` is the number of chunks
currently indexed.

## Tech stack

| Layer              | Technology                                                     |
| ------------------ | -------------------------------------------------------------- |
| Web API            | FastAPI + Uvicorn                                               |
| Text parsing       | pdfplumber (PDF), python-docx (DOCX)                            |
| Embeddings         | sentence-transformers — `all-MiniLM-L6-v2`, 384-dim             |
| Vector store       | FAISS (`IndexFlatIP` + texts sidecar file)                      |
| LLM                | Ollama (local) — `llama3.2:3b`                                  |
| Tests              | pytest + FastAPI `TestClient`                                   |

## Project layout

```text
app/
  api.py         FastAPI routes: /upload, /ask, /health
  parser.py      PDF/DOCX → plain text
  chunker.py     text → ~500-char chunks (50 overlap)
  embeddings.py  text → 384-dim vectors (all-MiniLM-L6-v2)
  store.py       FAISS index + chunk-text storage & persistence
  llm.py         question + chunks → Ollama → answer
tests/
  test_api.py    endpoint + pipeline tests (real-Ollama test auto-skips)
data/
  samples/       sample documents (ask_sample.docx is used by the tests)
  uploads/       uploaded files (gitignored)
  indexes/       saved FAISS index (gitignored)
requirements.txt
```

## Prerequisites

- **Python 3.11+** (3.13 recommended — 3.14 may emit warnings with this pinned stack)
- **Ollama**, with the model pulled:

  ```powershell
  ollama pull llama3.2:3b
  ```

- Git (recommended). No cloud accounts, no API keys.

The first time you upload a file, the embedding model `all-MiniLM-L6-v2` (~90 MB) is
downloaded from HuggingFace and cached locally — happens once, then it's fast.

## Setup

```powershell
# 1. Create the virtual environment (once)
python -m venv venv

# 2. Install dependencies (always from the venv!)
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Launch

```powershell
# 1. Make sure Ollama is running — the Ollama desktop app does this, or in a terminal:
ollama serve

# 2. Start the API (leave this terminal running)
.\venv\Scripts\python.exe -m uvicorn app.api:app --reload
```

Then open **http://127.0.0.1:8000/docs** — FastAPI's interactive console lets you
upload a file and ask questions right from the browser, no curl needed.

## Try it

1. Upload a sample document:

   ```powershell
   curl.exe -F "file=@data/samples/ask_sample.docx" http://127.0.0.1:8000/upload
   # {"filename":"ask_sample.docx","chunks":11,"pages":null,"index_total":11}
   ```

2. Ask a question about it:

   ```powershell
   curl.exe http://127.0.0.1:8000/ask -H "Content-Type: application/json" -d "{\"question\":\"What was the revenue?\"}"
   ```

3. Health check:

   ```powershell
   curl.exe http://127.0.0.1:8000/health
   ```

> Use **`curl.exe`**, not `curl` — in PowerShell `curl` is an alias for
> `Invoke-WebRequest` and won't behave like the examples above.

## API reference

| Method | Path      | Body                                    | Returns                                        | Errors                          |
| ------ | --------- | --------------------------------------- | ---------------------------------------------- | ------------------------------- |
| POST   | /upload   | multipart file (`.pdf` / `.docx`)       | `filename`, `chunks`, `pages`, `index_total`   | 400 unsupported type / bad file |
| POST   | /ask      | `{"question": "..."}`                   | `question`, `answer`, `results` (top-5)        | 400 empty/too-long question, or nothing indexed yet |
| GET    | /health   | —                                       | `status`, `index_total`                        | —                               |

## Running the tests

```powershell
.\venv\Scripts\python.exe -m pytest tests -v
```

Seven tests cover the pipeline end-to-end. The last one (`test_ask_with_real_ollama`)
actually calls your local Ollama — if it isn't running, pytest **skips** it (shown as
`s`, not a failure), so the suite passes in any environment.

## Troubleshooting

- **VS Code says imports "cannot be resolved"** → wrong interpreter. Bottom-right of
  VS Code → select `venv`. `.vscode/settings.json` pins the path.
- **`ImportError: cannot import name 'cached_download' from 'huggingface_hub'`** →
  stale pins — an old pinned package met a newer dependency. This project uses
  `sentence-transformers ~= 5.7.0`; upgrade the *direct* package, don't unpin
  everything.
- **`NameError: pdfplumber is not defined`** → you imported the class instead of the
  module. Use `import pdfplumber`, then `pdfplumber.open(...)`.
- **`cannot import name 'Documents' from 'docx'`** → it's `Document` (singular).
- **`/ask` answers `"Unable to generate an answer: ..."`** → Ollama isn't running
  (`ollama serve`), the model isn't pulled (`ollama pull llama3.2:3b`), or the request
  timed out.
- **pip prints a weird "exit code 1" in PowerShell** → often just PowerShell wrapping
  stderr. Check `$LASTEXITCODE` and the actual pip message.
- Read tracebacks **bottom-up** — the last line is the real error.
